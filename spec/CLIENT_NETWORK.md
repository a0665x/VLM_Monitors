# Private client camera network

## Roles and entry points

- `./run.sh` manages the Linux host service and inference engines. `/` remains the complete shared control workspace.
- `/join` is the QR landing page: immediately attempts to play a live source, without the old role gate. Watch and Publish are two tabs in the same page. `/join?mode=publish` opens the publishing tab.
- QR codes generated by `/api/share/qr.svg` now target the private HTTPS `/join` URL.
- All phones are clients. A phone can keep publishing while it switches to the watching tab. Video travels via MediaMTX on the host; this is a hub topology rather than a phone-to-phone mesh.
- Each browser has a remembered device label and a random per-tab publisher ID, preventing different phones or tabs from overwriting each other.

## Guided connection

The expandable connection guide explains installing/logging into Tailscale, checking device status in `https://console.tailscale.com/admin/machines`, and returning to the page. The page does not access the administrator's account or claim to inspect the phone's VPN app. A successful API request means the service is reachable; host Serve configuration is reported separately.

Users unable to open the private URL must enable Tailscale first. The landing page cannot diagnose a VPN problem before the browser can load it.

## Media network

On native service startup, when private Serve is active, `prepare_media_config()` derives `temp/mediamtx.tailnet.yml` from the loopback config. It binds WebRTC UDP and TCP 8189 specifically to the host's current Tailscale IPv4 address and advertises that address as an ICE candidate. HTTP signaling stays on loopback 8889. The MediaMTX discovery API binds to loopback 9997. No public interface listener or router port forwarding is created.

`/proxy/webrtc/<resource>` forwards same-origin GET/OPTIONS/POST/PATCH/DELETE to the fixed MediaMTX loopback upstream. It preserves SDP bodies, ETag, If-Match, Link, and rewrites Location back under the proxy. This supports embedded WHEP playback and WHIP publishing through Tailscale Serve HTTPS. Tailscale access policy must allow 443 and media UDP/TCP 8189. Enabling Serve alone does not transport the WebRTC media channel.

The `./run.sh local-tailnet` command restarts an active native monitor service to derive this profile. After enabling Serve manually, restart the native monitor service once. This configuration automation applies to the bundled native loopback profile; custom/Docker media configurations require equivalent reachable ICE candidates and ports.

## Watching and publishing

- WebRTC is the default playback. HLS is a user-selectable compatibility fallback through the existing same-origin proxy; HLS can add delay.
- `/api/network` combines known camera labels with MediaMTX `ready` paths. Heartbeats alone never imply live video on the client page.
- Viewer source selection stays local to that browser. The separate “交給主機 AI 監控” action changes the global inference source. There is currently one shared analysis loop, not one loop per phone.
- Publishing requires an explicit Start click and browser media permission. Camera name, front/back lens, and optional microphone are available. H264 is selected for playback and RTSP/OpenCV compatibility; microphone is off by default.
- Source registration starts only after the WHIP connection succeeds. On errors the MediaMTX client retries; UI reports the failure. Stop closes the peer connection, stops every media track, unregisters the source and releases the optional screen wake lock.
- Keep mobile browsers foregrounded and the screen awake. Mobile operating systems may suspend capture when backgrounded or locked; a web page cannot guarantee persistent background camera capture.
- Access currently follows the private Tailnet and shared application controls. There are no separate viewer/publisher accounts or per-camera authorization rules in this application.

## Entry simplification (2026-09-26)

The host homepage now displays a persistent QR card above the camera workspace. The previous first-visit role gate and remembered-role redirect are bypassed so the host always opens its workspace. Every client page, including the publishing tab, has a visible “加入其他手機” button with the same QR code.

The client defaults to “查看所有相機”, rendering live camera tiles together. Selecting a tile opens an enlarged view; playback settings and AI controls are secondary disclosures. “分享我的相機” stays available as the other primary tab. The architecture illustration and “你的相機網路” wording were removed. Publishing continues when switching these tabs.

`./run.sh` now offers `a) 一鍵準備主機與手機連線`. On a clean installation this is the default option. It installs required components (including official Tailscale when missing), starts the host, guides the operator through Tailscale login and private sharing, and directs them to the homepage QR. Account login, sudo credentials, and any first-time HTTPS enablement still require the operator. The existing-host default remains Start Service. This host reused its existing installation; a fresh OS install was not run.
